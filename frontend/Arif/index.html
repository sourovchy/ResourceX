Project Overview & Tech Stack
§01

Many students on campus own high-value items — cycles, DSLRs, Arduino kits, laptops, event equipment — that sit idle most of the time. Other students urgently need them but cannot afford to buy. ResourceX digitizes this peer-to-peer sharing with trust, accountability, and a built-in micro-economy. The entire platform runs in the browser — no mobile app required.

🏗️

Architecture Decision: Two separate Next.js apps — one student-facing web app (port 3000) and one admin-only panel (port 3001) — both backed by the same Spring Boot REST API (port 8080) and MySQL database.

User Roles & Authentication
§02
⚠️

Key Change from ResourceX v1: There are now only 2 roles — ADMIN and STUDENT. A Student can act as both an Owner (lister) and a Renter (borrower) simultaneously. No separate Owner role needed.

👑 ADMIN
  • Created directly in database (not via signup)
  • Has full governance access over the platform
  • Uses the separate admin web panel (port 3001)
  • Verify/suspend students, approve/reject items
  • Resolve disputes, override penalties
  • View analytics & system reports
  • Manage categories & announcements
  • Trust Score audit and manual override
🎒 STUDENT (Owner + Renter)
  • Registers via campus email + student ID
  • Requires admin verification before access
  • Uses the student web app (port 3000)
  • As Owner: List items, approve bookings, report damage
  • As Renter: Browse items, send booking requests, pay deposit
  • Both roles active simultaneously — same account
  • Has Trust Score that affects platform privileges

Authentication Flow

1Student RegistrationCampus email + Student ID + Password → Account created with status: PENDING

Student Web App — All Pages

The student web app is a Next.js 14 project. Every verified student has both Owner and Renter capabilities inside the same account. The main navigation reflects this dual role.

Admin Panel — All Pages
§05

The admin panel is a separate Next.js 14 project running on port 3001. All routes require an ADMIN JWT. Middleware redirects to /admin/login if no valid token is found.

🔐 Admin Auth
/admin/login Email + password. On success, checks JWT role === ADMIN. If STUDENT → "Access Denied". If ADMIN → redirect to /admin/dashboard.
📊 Dashboard & Analytics
/admin/dashboard Stat cards: Total Users, Active Rentals, Overdue Rentals, Pending Disputes, Total Items, New Registrations today. Pending verifications table (quick Verify buttons). Recent dispute list. Platform health overview.
/admin/analytics Charts — Top 5 most rented items, Monthly rental revenue, Late return stats by user, Active vs completed bookings ratio, User growth over time, Category distribution pie chart.
👥 User Management
/admin/users Searchable table: Name, Email, Student ID, Status, Trust Score, Total Bookings, Registered Date. Filter by status (PENDING / VERIFIED / SUSPENDED). Actions: Verify, Suspend, View Profile.
/admin/users/[id] Full user detail view. All profile info, booking history, items listed, trust score log, reviews, disputes. Admin can manually adjust trust score with reason. Suspend / Reactivate button.
📦 Item Moderation
/admin/items All items table. Filter: Pending Approval / Active / Rejected / Inactive. Actions: Approve, Reject with reason. Each row shows: title, owner, category, price, submitted date.
/admin/items/[id] Full item detail. Photos, description, category, owner info. Approve or Reject buttons. Rejection requires a reason (sent as notification to owner).
📋 Booking Monitor
/admin/bookings All bookings across platform. Filter by status, date range, user. Highlight overdue rentals in orange. Admin can override booking status if needed. View booking details.
⚖️ Dispute Center
/admin/disputes All disputes. OPEN disputes highlighted. Each dispute card: booking ID, raised by, reason, evidence. Resolve form with admin decision text area. Calls PUT /api/admin/disputes/{id}/resolve. Decision sent as notification to both parties.
💰 Penalty Override & Trust Score
/admin/penalties Pending penalty requests from owners. Review reason + amount. Actions: Approve (deduct from deposit), Modify amount, Waive (dismiss). Each action updates payment record.
/admin/trust-scores View all users' trust scores. Full audit log of every change: user, change value, reason, timestamp. Manual override: adjust score + add reason (logged in trust_score_log).
⚙️ Platform Settings
/admin/categories Add, edit, delete item categories. Category name + description. Cannot delete a category that has active items.
/admin/announcements Post campus-wide notices. Title + body. Appears in all students' notification feeds. List of past announcements with edit/delete.

Key SQL — Booking Conflict Check

-- Check before INSERT into bookings
SELECT * FROM bookings
WHERE item_id = ?
  AND status NOT IN ('CANCELLED', 'REJECTED')
  AND (start_date <= ? AND end_date >= ?);
-- If row returned → throw BookingConflictException (HTTP 409)

Trust Score Trigger

CREATE TRIGGER update_trust_on_return
AFTER UPDATE ON bookings FOR EACH ROW
BEGIN
  IF NEW.status = 'COMPLETED' AND NEW.end_date >= CURDATE() THEN
    UPDATE users SET trust_score = trust_score + 5
    WHERE user_id = NEW.renter_id; -- on-time return: +5
  ELSEIF NEW.status = 'COMPLETED' AND NEW.end_date < CURDATE() THEN
    UPDATE users SET trust_score = trust_score - 10
    WHERE user_id = NEW.renter_id; -- late return: -10
  END IF;
END;

Key Business Logic
§11

🔀 Role-Based Redirect

Login API returns {token, role}. Frontend checks role: ADMIN → router.push('/admin/dashboard'), STUDENT → router.push('/dashboard'). Middleware.ts re-checks on every page load.

📅 Booking Conflict Check

Before creating a booking, query DB for overlapping active bookings on same item. Overlap found → throw BookingConflictException → return HTTP 409 to client.

⭐ Trust Score Engine

COMPLETED on time: +5. COMPLETED late: -10. Damage reported: -20. Every change logged in trust_score_log. High-value items require minimum score threshold.

💰 Deposit & Penalty Flow

Deposit recorded at booking. Return completed → if no penalty: Released. Owner raises penalty → Admin approves → Deducted. If penalty > deposit → user flagged.

🛡️ JWT Security

JWT contains userId + role. 24-hour expiry. JwtFilter validates every request. Spring Security @PreAuthorize by role. Admin routes: hasRole('ADMIN') only.

👤 Dual Role (Student)

Same user_id can own items AND make bookings. The DB does not restrict this. Frontend shows owner actions in /my-posts, renter actions in /borrow — same account, separate UX contexts.
